## Phase Goal

**As a** buyer, **I want to** open the site (locally, under any base path) and filter, sort, and search a poster grid of seed DVDs, **so that** I can find a movie I want in seconds — backed by one schema-validated catalog file that both the SPA and the ingestion scripts share.

<objective>
Harden the data contract the walking skeleton locked: make the validate gate's failure modes permanent tests (malformed entry, duplicate slug/key, non-canonical bytes, empty catalog, missing file), prove the canonical writer is deterministic and atomic, pin the slug/normalization rules with unit tests, and wire the light ESLint + Prettier setup D-35 asks for. Nothing here changes behavior a buyer sees; it makes the guarantees in success criteria 4 and 5 ("build fails loudly", "no-op rewrite produces an empty diff", "no keys anywhere") mechanically checked on every `npm test`.

Purpose: Phase 3's `enrich.ts` and Phase 4's skill will write through `writeCatalog()` and be judged by `validate.ts`; these tests are the contract they inherit.
Output: Four Vitest suites, `DVD_CATALOG_PATH` override in the CLI, lint/format config, `.env.example`.
</objective>
